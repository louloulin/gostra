# 事件驱动工作流示例 (Event Workflow Example)

这个示例展示了如何使用 Gostra 的事件驱动工作流系统处理需要等待外部事件的业务流程。

## 概述

事件驱动工作流是一种特殊类型的工作流，它能够：

1. 在执行过程中暂停，等待外部事件
2. 根据不同的事件类型选择不同的执行路径
3. 保存和恢复工作流状态
4. 支持长时间运行的业务流程

## 示例说明

本示例模拟了一个完整的订单处理流程：

1. **创建订单**：初始化订单信息
2. **等待支付**：工作流暂停，等待用户完成支付
3. **履行订单**：用户支付后，处理订单并准备发货
4. **发货**：订单发货，等待送达确认
5. **完成订单**：确认送达后，标记订单为完成状态

示例还包含了订单取消的流程，展示了如何处理多分支事件路径。

## 关键概念

- **事件类型 (EventType)**：标识不同类型的事件，如 "payment-completed", "delivery-confirmed" 等
- **工作流状态 (WorkflowState)**：保存工作流执行状态，包括当前步骤、结果数据等
- **暂停/恢复**：工作流可以在特定步骤暂停，等待外部事件后恢复执行
- **状态存储**：支持内存存储和文件存储两种方式保存工作流状态

## 运行示例

```bash
go run main.go
```

运行后，你将看到订单流程的完整模拟，包括：

1. 订单创建
2. 等待支付（工作流暂停）
3. 用户支付（发送事件）
4. 订单处理和发货
5. 确认送达（发送事件）
6. 订单完成

以及一个简化的订单取消流程示例。

## 与 Mastra 工作流的对比

本实现参考了 Mastra 的事件驱动工作流设计，但针对 Go 语言和 Actor 架构进行了适配：

1. 使用 Go 的并发特性（goroutines, channels）处理异步事件
2. 支持步骤之间的事件条件路由
3. 实现状态持久化，支持长时间运行的工作流
4. 提供 API 接口，方便集成到 Web 服务
